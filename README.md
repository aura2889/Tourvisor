# Турвизор · Актау

Самые дешёвые туры из Казахстана в **Дубай** (только сам Дубай), **Китай** и **Грузию** (акцент на Кудаури) по данным [tourvisor.ru](https://tourvisor.ru).
Город вылета не выбирается: приложение смотрит вылеты из Актау, Астаны и Алматы и показывает, откуда сейчас дешевле.
Даты тоже не выбираются: список идёт от самой низкой цены, одинаковые цены на разные даты склеены в диапазоны.

Приложение: `https://aura2889.github.io/Tourvisor/` (на телефоне: «Добавить на главный экран»).

## Что показывает
- Направление: Дубай / Китай / Грузия (у Грузии по умолчанию курорт Кудаури, остальные — чипами).
- Чипы городов вылета с минимальной ценой, самый дешёвый первым; ▼/▲ — цена ниже/выше, чем в прошлый сбор.
- Вкладки «Туры» и «🔥 Горящие»; звёзды 3★ 4★ 5★ (по умолчанию все три); сортировка по цене или по ближайшей дате.
- Карточка: цена за 2 взрослых, отель, курорт, ночи, питание, даты, чартер/регулярный, туроператор; по нажатию — другие варианты и ссылка на Турвизор.

## Как устроено
1. GitHub Actions каждый день в 03:03 по Актау (GitHub может опоздать на 1–3 часа, но до 6 утра укладывается) запускает `scraper/tourvisor_scraper.py`.
2. Парсер открывает Турвизор в headless-браузере (Playwright) по каждому направлению и городу вылета, забирает JSON-ответы сайта, а если их нет — текст карточек.
3. `scraper/aggregate.py` оставляет отели от 3★, убирает Абу-Даби/Аджман и т.п., склеивает даты, считает минимумы и историю.
4. Результат — `data.json` и `status.json`; приложение (`index.html`) их читает.
Если по какому-то городу сбор упал, остаются вчерашние данные с пометкой «данные за прошлый сбор».

## Первый запуск (важно)
Парсер написан без доступа к Турвизору (из среды разработки сайт был закрыт), поэтому до первого реального запуска это «слепой» код:
1. Settings → Pages → Branch `main` / root — включить приложение.
2. Actions → «Ежедневный сбор Турвизора» → Run workflow → режим **recon** (разведка). Она сохранит в `debug/recon/` страницы, скриншоты, JSON-ответы сайта и найденные id городов.
3. По результатам разведки парсер подгоняется (id городов вылета Казахстана, id Грузии, формат ответов). После этого — режим **scrape**.
Пока сбор не настроен, приложение показывает тестовые данные (жёлтая плашка).

## Файлы
- `index.html`, `sw.js`, `manifest.json` — приложение (PWA)
- `config.json` — города вылета, направления, звёзды, число взрослых, паузы; `departure_ids` / `country_ids` можно задать вручную, если автопоиск не нашёл
- `scraper/tourvisor_scraper.py` — сбор (режимы `scrape`, `recon`, `demo`)
- `scraper/aggregate.py` — фильтры, склейка дат, история; тесты: `python scraper/test_aggregate.py`, `python scraper/test_extract.py`
- `scraper/demo_data.py` — тестовые данные (`--mode demo`)
- `.github/workflows/daily.yml` — расписание

## Если Турвизор не отдаёт данные
Самая вероятная причина — блокировка серверов GitHub. Тогда тот же скрипт запускается на своём ПК/VPS
(`pip install -r scraper/requirements.txt && playwright install chromium && python scraper/tourvisor_scraper.py`, затем `git push`).
